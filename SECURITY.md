# Security scope and reporting

This is a local alpha candidate. Permission Simulator analyzes
explicit declarations; Crash Lab executes authorized controlled fixtures in a
restricted local container. Neither establishes complete effective permissions,
all side effects, trusted imported evidence or hostile-code containment.

See [security model](docs/SECURITY_MODEL.md) and
[integration coverage](docs/INTEGRATIONS.md) before use. The live Claude Code
adapter is deferred; no managed execution service or cloud offering is available.
Use synthetic data and selected source without credentials. Runtime network is
off, host data mounts are absent, resource use is bounded and cleanup is scoped.
Selected code/arguments remain in local image caches after containers are removed.

No public security contact or private vulnerability-reporting channel has been
configured or verified for the intended repository. The release owner must
configure and verify one before publication; do not claim an enabled GitHub
reporting feature or invent an email address. Do not put credentials, customer
data or a sensitive reproduction into a public issue. For this local candidate,
report concerns directly to the project owner through the existing collaboration.

Only the exact tested versions and platform are verified; see
[compatibility](docs/COMPATIBILITY.md). Dependency and image scans cover known advisories,
not absence of vulnerabilities. Review and rerun them before any release. No
automatic update, vulnerability triage SLA or support window is promised.
